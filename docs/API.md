# API reference

Base URL: the value of PUBLIC_API_BASE_URL. Management bot API URLs end in /v1.

## Authentication

Send the generated key in the X-API-Key header or as an Authorization: Bearer header. Keys are generated by the Telegram management bot and are displayed only once. The server stores only a peppered HMAC digest; the original secret cannot be retrieved.

Example request:

    curl -H "X-API-Key: $MUSIC_API_KEY" "$MUSIC_API_URL/search?q=sample"

Do not put API keys in query parameters, URLs, source control, logs, or public messages.

## Endpoints

### Health

- GET /health/live — process liveness, no authentication.
- GET /health/ready — database readiness, no authentication.

### API information

- GET /v1 — basic API information. No audio or private data is returned.

### Search catalog

- GET /v1/search?q=<query>&limit=<n>
- Requires an API key.
- q: 1–200 characters.
- limit: 1–50, default 10.
- Searches active local tracks by title, artist, and album.

Example:

    curl -H "X-API-Key: $MUSIC_API_KEY" "$MUSIC_API_URL/search?q=night&limit=10"

The response has query, count, and items. Track records contain a stable id, title, artist, album, duration_seconds, mime_type, file_size, and created_at. Internal filesystem paths are never returned.

### Track metadata

- GET /v1/tracks/{track_id}
- Requires an API key.
- Returns metadata for one active catalog track.

### Short-lived playback URL

- GET /v1/tracks/{track_id}/playback
- Requires an API key.
- Returns track metadata, a signed URL, and expires_in.
- The signed URL is valid for the configured PLAYBACK_URL_TTL_SECONDS (1–3600 seconds). Revoking the issuing key invalidates its playback URLs.

Example:

    curl -H "X-API-Key: $MUSIC_API_KEY" "$MUSIC_API_URL/tracks/0123456789abcdef01234567/playback"

Use the returned url as the media input for a compatible player/FFmpeg process. The URL is a bearer credential until it expires, so do not publish or log it.

### Stream

- GET /v1/streams/{track_id}?kid=...&exp=...&sig=...
- Uses a signed playback URL rather than an API-key header, which is useful for audio clients that cannot set custom headers.
- The service verifies signature, expiry, key status, catalog status, and filesystem containment before serving the file.
- Supports the HTTP behavior provided by Starlette's FileResponse. Treat every signed URL as secret until it expires.

## Errors

- 401 — missing, malformed, invalid, revoked, or expired API key.
- 403 — invalid/expired playback signature or revoked playback authorization.
- 404 — track is not in the active catalog or its file is unavailable.
- 429 — per-key rate limit exceeded.
- 503 — authentication configuration, rate-limit service, or readiness problem.

## Authorized source policy

This API indexes a local audio directory. Put only audio you own, have licensed, or otherwise have permission to stream into that directory. This implementation intentionally does not scrape websites, reverse-engineer private downloader endpoints, bypass DRM, or work around third-party platform access controls.
